# Automated Changelog Instructions for holmgard-lore-mcp

These are instructions for applying the same automated changelog solution to the
`holmgard-lore-mcp` sibling project (the Cloudflare Worker MCP backend).

## Context

The `holmgard-lore-editor` repo has been updated to:
- Remove the per-PR `CHANGELOG.md` manual requirement
- Auto-generate `CHANGELOG.md` from conventional commits (`feat:`/`fix:`) at release time
- Add a `workflow_dispatch` release workflow that handles versioning + changelog + GitHub Release

Apply the same pattern here, adapted for a Cloudflare Worker deployment.

---

## Changes to make

### 1. Remove any per-PR changelog check

Check `.github/workflows/` for any job that blocks PRs on CHANGELOG.md edits.
If present, delete that job (keep any other quality checks).

Check `scripts/` or `package.json` scripts for a local pre-push changelog check.
Remove it.

### 2. Add `conventional-changelog-cli`

In `package.json`:
- Add to `devDependencies`: `"conventional-changelog-cli": "^5.0.0"`
- Add script: `"changelog": "conventional-changelog -p angular -i CHANGELOG.md -s"`

### 3. Clean up CHANGELOG.md

If the file has duplicate sections, synthetic version history, or an
`[Unreleased]` section referencing versions not yet tagged in git, consolidate
to a single accurate history. Leave real `[Unreleased]` entries in place.

Add a note at the top after the header:

```
> **Note:** From the next release onward this file is auto-generated by
> `conventional-changelog-cli` during the release workflow. Do not edit manually.
```

### 4. Create `.github/workflows/release.yml`

This is a Cloudflare Worker, so the release workflow differs from the Tauri app:
- No `src-tauri/tauri.conf.json` to bump
- Deploy step uses Wrangler instead of `tauri build`

```yaml
name: Release

on:
  workflow_dispatch:
    inputs:
      version:
        description: 'Version to release (e.g. 0.2.0)'
        required: true
        type: string

permissions:
  contents: write

jobs:
  release:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
          token: ${{ secrets.GITHUB_TOKEN }}

      - uses: pnpm/action-setup@v4.0.0
        with:
          version: '11.5.1'           # match the project's pnpm version

      - uses: actions/setup-node@v4
        with:
          node-version: '22'
          cache: 'pnpm'

      - name: Install dependencies
        run: pnpm install --frozen-lockfile

      - name: Bump package.json version
        run: npm version ${{ inputs.version }} --no-git-tag-version

      - name: Generate CHANGELOG.md
        run: pnpm changelog

      - name: Commit and tag release
        run: |
          git config user.email "github-actions[bot]@users.noreply.github.com"
          git config user.name "github-actions[bot]"
          git add package.json CHANGELOG.md
          git commit -m "chore: release v${{ inputs.version }}"
          git tag "v${{ inputs.version }}"
          git push origin main --follow-tags

      - name: Extract release notes
        run: |
          node -e "
            const fs = require('fs');
            const log = fs.readFileSync('CHANGELOG.md', 'utf8');
            const version = '${{ inputs.version }}';
            const match = log.match(new RegExp('## \\\\[' + version.replace(/\./g, '\\\\.') + '\\\\][^\\n]*\\n([\\s\\S]*?)(?=\\n## \\\\[|\$)'));
            const notes = match ? match[1].trim() : 'See CHANGELOG.md for details.';
            fs.writeFileSync('/tmp/release-notes.txt', notes);
          "

      - name: Create GitHub Release
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
        run: |
          gh release create "v${{ inputs.version }}" \
            --title "v${{ inputs.version }}" \
            --notes-file /tmp/release-notes.txt

      # Optional: deploy to Cloudflare Workers on release
      # - name: Deploy to Cloudflare Workers
      #   run: pnpm wrangler deploy
      #   env:
      #     CLOUDFLARE_API_TOKEN: ${{ secrets.CLOUDFLARE_API_TOKEN }}
```

Adapt the `pnpm/action-setup` version to match whatever `pnpm` version the MCP project uses.
Uncomment the deploy step if you want releases to auto-deploy to Workers.

### 5. Update any agent work-order template

If the repo has an `agent-trigger.yml` (or similar) with a step telling agents
to update `CHANGELOG.md`, remove that step and update the key requirements
section to remove the CHANGELOG.md mention.
